## 1. System Overview & Architecture

`learnings-factory` (npm package `paul-learnings`) is a **static, zero-dependency, GitHub Pages** educational hub. Per `PRODUCT.md`, the stack is "zero-dependency static HTML/CSS/ES modules, Node standard-library tests". There is no build step; `.github/workflows/pages.yml` uploads exactly the committed `site/` tree.

Components:

- **Static site** (`site/`) — a hub plus topic pages. Decision-model pages (`decision-models/`) let a reader inspect typed requests/probabilities, run on-device inference, or query hosted providers. Neural-network pages (`neural-networks/`) render pure-math visualisations with inline SVG/canvas.
- **On-device inference engines** — `site/decision-models/kev-engine.js` (ONNX Runtime Web / JSEP-WASM, from `onnx-community/kev-0.6b-ONNX`) and `site/decision-models/laya-engine.js` (LiteRT.js, from `litert-community/Laya-Multilingual-LiteRT`). Weights download on demand from Hugging Face, are pinned to immutable commit revisions, and are verified against published/pinned SHA-256 digests with streaming byte caps.
- **Hosted-provider adapters** — `core.js` (`decide`/`generate`), `playground.js`, and `image-lab.js` call `api.typesafe.ai`, `api.openai.com`, and `api.anthropic.com` with the reader's own key, read from a memory-only password field.
- **Local dev server/relay** — `scripts/serve.mjs` serves `site/` on loopback and relays `/api/{jev,openai,claude}` POSTs to the three fixed upstreams.
- **Fixture downloader** — `scripts/fetch-kev-fixtures.mjs` fetches pinned Kev artifacts to `/tmp/kev-files` and verifies each against a hash.
- **Tests** — Node `--test` suites plus a browser smoke driver, used as executable security policy (see §6).
- **Vendored runtimes/weights** — `site/vendor/` (ORT bundle, LiteRT/emscripten JS, HF tokenizers) and `site/decision-models/laya/` (tokenizer, graphs, sums, licenses).

Operational environment: GitHub Pages (HTTPS, no custom headers, no server code) for readers; local Node 22 (`npm run serve`) for the optional relay. All state is per-tab; keys are memory-only and there is no analytics, external font, or runtime CDN.

## 2. Trust Boundaries & Actors

Actors:

- **System owner / developer** — authors the repo, vendors runtimes and weights, runs `npm run serve` and `npm run fetch:kev`. Trusted for code, manifests, and CI configuration.
- **End user / reader** — supplies an idea/spec/question JSON, a state text, an image, and optionally their own API keys; reads the probabilities and (in demos) clicks "Apply". Trusted for their own inputs and secrets; their browser is the enforcement point for network policy.
- **Untrusted web content** — text a reader may paste as the decision `state` (e.g. an email or ticket), dropped/pasted images, and any provider JSON that comes back over the wire.
- **External APIs / hubs / CDNs** — `huggingface.co` (+ `*.hf.co` redirects), `api.typesafe.ai`, `api.openai.com`, `api.anthropic.com`. Untrusted for content; authenticated by the reader's key or by pinned digests.

Boundaries crossing which data/control flows:

1. **Browser page ↔ external model/API hosts.** Reader key + state/questions/image cross outbound (only on explicit action); provider JSON crosses inbound and is validated before rendering. `site/index.html` and the decision pages declare `connect-src` listing exactly these hosts plus loopback.
2. **Browser page ↔ loopback local inference/relay.** `core.js:loopbackEndpoint` and the `serve.mjs` relay are the only local endpoints; the relay injects provider credentials only into the three fixed upstreams.
3. **Digest boundary.** Weight/artifact bytes from Hugging Face must match a pinned SHA-256 before being handed to a runtime (`kev-engine.js:fetchVerified`, `laya-engine.js:fetchBytes`).
4. **Render boundary.** Caller/provider-derived strings must reach the DOM only as text.
5. **Repo ↔ CI ↔ published site.** Only committed `site/` bytes are published; actions are SHA-pinned.

## 3. Explicitly Trusted (Non-Threats)

Audits and discovery agents should **not** flag the following as vulnerabilities:

- **Local loopback listener** — `scripts/serve.mjs` binds `127.0.0.1` and rejects requests whose `Host` is not the printed `127.0.0.1:<port>`; `/api/` requires a same-origin `Origin`, `POST`, `application/json`, and one of three fixed routes. A loopback-bound dev listener is a trusted component (see §7 for the accepted header-only authorization model). Candidate `ep-16`.
- **Empty-string DOM clears** — `containerEl.innerHTML = ""` (`site/neural-networks/steppers.js:84`, candidate `ep-1`), `e.innerHTML = ""` (`site/neural-networks/widgets.js:37`, `ep-2`), and `container/listEl.innerHTML = ""` (`site/opt-chronicles/app.js:394,425,430`, `ep-12/13/14`) clear a container before appending nodes created with `textContent`. These are not injection sinks. They are additionally covered by `tests/lint.test.js`, which permits only `.innerHTML = ["']\s*["']` clears.
- **Constant-only notice strings** — `notice.innerHTML = '<strong>…'` in `site/decision-models/image-lab.js:1129,1132,1135` (candidates `ep-5/6/7`) are quoted string literals with no interpolation; `tests/lint.test.js` allows exactly this constant form, and only in `image-lab.js`, via `NOTICE_CONSTANT_LINE`.
- **Reader-supplied secrets** — API keys are read from `input[type=password]` and kept in memory only; there is no `localStorage`, `sessionStorage`, `document.cookie`, or other persistence of keys anywhere in `site/`.
- **Loopback inference endpoints chosen by the reader** — `core.js:loopbackEndpoint` deliberately accepts any port on exactly `localhost`, `127.0.0.1`, or `[::1]` (with `http`/`https`, path exactly `/v1/systemone`, and no credentials/query/fragment). The field exists so a reader can point at their own local server; any-port on loopback is intentional.
- **Developer test suites and fixtures** — `tests/` and `tests/fixtures/` are local test artifacts and trusted.
- **The `client` demo engine** — the image lab's "Demo Mode / Schema Preview" is an explicitly labelled, deterministic fixture (`simulated: true`) and is deliberately not gated by `validateAnswers`; it executes no model and no external action.

## 4. Untrusted Attack Surfaces

- **Model/artifact downloads from Hugging Face.** Untrusted bytes crossing into `fetchVerified`/`fetchBytes`. Controls: immutable commit-revision pins (`KEV_REVISION`, `LAYA_REVISION`), required per-artifact SHA-256 (missing digest throws), streaming byte caps (`KEV_MAX_BYTES`, `LAYA_MAX_BYTES`, defaults), `Content-Length` pre-check, and `AbortController` cancel-on-overflow (`tm-unbounded-download-buffer`). Candidates `ep-8/9/10/15`.
- **Hosted-provider JSON.** `api.typesafe.ai`, OpenAI, and Anthropic responses cross the render boundary. Controls: `validateAnswers`/`validateSpec` before render; exact answer-id-set match; distribution-sum, finiteness, and range checks; 45 s `AbortSignal`. Candidates `ep-3/4/11`.
- **Reader-pasted text packed into a model sequence.** `kev-pack.js:packDecision` and `laya-pack.js:buildSequence` build sequences from caller text. Kev neutralizes delimiters via `escapeUserText` (`<|name|>` → `<¦name¦>`); Laya neutralizes the full special-token vocabulary through the same shared `neutralizeReaderText`/`specialLiteralsFromTokenizer` in `tokenizer-specials.mjs`, applied to instructions, option text and serialized state (`laya-pack.js:130/137/160`), so the hardening cannot drift between the two engines (learnings-iif; RESOLVED finding `tm-laya-special-token-neutralization`).
- **Dropped/pasted images and user question JSON.** `image-lab.js` reads files only when `file.type.startsWith('image/')`, previews through an `<img>`, and validates the payload as `data:image/*`/`blob:` plus `validateSpec` before any provider call.
- **Vendored third-party runtime code.** `site/vendor/**` (ORT bundle, LiteRT/emscripten, tokenizers) is third-party code executing with full page privileges and is excluded from the innerHTML lint walk; see finding `tm-vendored-runtime-unverified`.
- **Loopback relay traffic.** Any local process that can open a loopback connection and set `Host`/`Origin` headers can drive the relay; the web-origin path is closed by the `Origin` check.
- **GitHub Actions supply chain.** `uses:` references are mutable unless pinned; the workflow pins every action to a full SHA and runs with `contents: read` + `pages: write` + `id-token: write`.

## 6. Security Invariants for Auditors

Check these; a violation is a likely vulnerability.

- **INV-CSP**: every HTML entry point ships `<meta http-equiv="Content-Security-Policy">` starting `default-src 'none'`, with `script-src 'self' 'wasm-unsafe-eval'` and an explicit `connect-src` allowlist. A new page without it is a regression.
- **INV-NO-INNERHTML**: no `.innerHTML`/`.insertAdjacentHTML`/`document.write` with interpolation outside `site/vendor/` (`tests/lint.test.js`). Only empty-string clears and the constant `notice.innerHTML` template in `image-lab.js` are allowed.
- **INV-DOM-TEXT**: all caller/provider-derived strings render via `textContent`, `append("string")`, or the local `el()`/`h()` helpers; note `el()`'s attribute loop still uses `setAttribute`, so attribute values must be constants.
- **INV-VALIDATE-PROVIDER**: externally derived JSON passes `validateAnswers` (and specs pass `validateSpec`) before any render; unexpected answer ids and out-of-set choices fail closed.
- **INV-PROTO-SAFE**: maps keyed by caller ids/labels use `Object.create(null)` (or validate ids first, as `validateSpec`'s `^[a-z][a-z0-9_]*$` + explicit `constructor/prototype/__proto__` rejection does).
- **INV-TIMEOUT**: every UI-blocking external call passes a bounded `AbortSignal` (`PROVIDER_TIMEOUT_MS === 45000`). Exported `decide`/`generate`/`decideImage` default the signal so direct callers are covered.
- **INV-FETCH-HYGIENE**: outbound requests set `redirect:'error'`, `credentials:'omit'`, and `referrerPolicy:'no-referrer'` where the provider allows it.
- **INV-LOOPBACK-HOST**: `loopbackEndpoint` permits exactly `localhost`/`127.0.0.1`/`[::1]`, `http`/`https`, path exactly `/v1/systemone`, no credentials/query/fragment.
- **INV-DIGEST**: every weight/artifact download requires a pinned `sha256`; an absent digest throws; the byte cap is enforced during streaming (before digest) with `AbortController`, not after `arrayBuffer()`.
- **INV-REVISION-PIN**: artifacts are fetched from commit-SHA revisions, never `main`; swapping a URL cannot bypass the digest (the digest is looked up by file, not by caller).
- **INV-KEY-MEMORY**: API keys live in password inputs and appear only in `Authorization`/`x-api-key` headers; no persistence and no logging of key values.
- **INV-RELAY**: `serve.mjs` binds `127.0.0.1`; rejects a mismatched `Host`; `/api/` requires same-origin `Origin`, `POST`, `application/json`, and a fixed route; enforces a 1 MiB body cap and `redirect:'error'`; forwards only `Content-Type` + `Authorization`/`x-api-key` (never `Cookie`). See §7 for the accepted residual.
- **INV-SUPPLY-CHAIN**: every `uses:` is a full 40-char SHA with a version comment; deploy permissions are minimal; `npm test` runs the lint/security suites before publish.
- **INV-SPECIAL-TOKENS**: user text must not be able to produce a structural special/delimiter token. Both engines do this: Kev with `escapeUserText`, Laya with the shared `neutralizeReaderText` over the tokenizer-derived special vocabulary (`tokenizer-specials.mjs`, learnings-iif). The former Laya-only-mask-string gap (`tm-laya-special-token-neutralization`) is RESOLVED; auditors should check any NEW packer reuses the shared neutralizer rather than hand-rolling one.

## 7. Explicit Exclusions (Wontfix / Accepted Risks)

- **Loopback server authorization is header-based.** `serve.mjs` protects the relay with `Host` + `Origin` + fixed-route checks rather than a secret. A local process can forge both headers, but local code execution already implies compromise, and web content cannot (it cannot set `Host`). Accepted residual; not an active finding.
- **Reader-supplied keys and outbound provider calls.** Sending a key and state/image to OpenAI/Anthropic/TypeSafe is the product's purpose, is user-initiated, and is disclosed in the UI (pinned by `learnings-mem` tests).
- **No authentication, accounts, or tenant isolation.** The site is public and stateless; there is nothing to authorize server-side.
- **`loopbackEndpoint` accepts any port on loopback**, intentionally, so readers can target their own server.
- **Duplicate JSON object keys collapse last-wins** before validation. This is an ECMAScript/RFC 8259 reality and is a documented, pinned limitation in `playground.js`; a raw-text duplicate detector was rejected as a second tokenizer that false-positives on `"` inside strings.
- **The Laya English checkpoint is disabled** and the vendored `en-SHA256SUMS` is a copy of the multilingual list with no `laya_en_*` rows; this gap only matters if English is ever enabled (documented in `laya-manifest.js`).
- **The `client` demo engine is ungated by design** (clearly labelled simulation) and executes no model or action.
- **Vendored runtime trust** is a deliberate build-time decision; it is recorded as a low supply-chain finding (`tm-vendored-runtime-unverified`) rather than an exploitable one.
