The Transformer

Inspect queries, keys, values and the row-wise softmax that mixes token information.

Attention is a learned lookup

Each token representation is projected into a query Q, key K and value V. A query’s dot product with every key gives compatibility scores. Softmax over keys makes a distribution; its weighted average of values is the output. Q and K choose where to read; V supplies what gets read.

Attention(Q,K,V)=softmax(QKTdk)V

If query and key components are independent, zero-mean and unit variance, their dot-product variance grows with dₖ. Dividing by √dₖ controls that scale. It is not a cosine normalization. The toy below fixes dₖ = 2 and displays every vector, so every cell can be checked by hand.

Masks, heads and grouping

A causal decoder masks future keys to −∞ before softmax, making their weights zero. An encoder can use bidirectional attention. Position information must enter separately; otherwise permuting input tokens just permutes attention’s rows and columns.

Multi-head attention (MHA) learns separate Q/K/V projections for each head, concatenates head outputs and applies an output projection. The heatmap above shows one head only. Multi-query attention (MQA) shares one K/V head across all query heads. Grouped-query attention (GQA) is in between: several query heads share each K/V head. Q head count stays fixed while K/V storage falls.

The calculator below compares 8 query heads with 8, 2 or 1 K/V heads. This is a cache-size calculation, not a simulation of learned multi-head behaviour. Fewer K/V heads can reduce decoding bandwidth, but model quality depends on training.
