How it runs: five backends

The same matrix product can travel through very different memory and execution systems.

One equation, several execution paths

For A[M,K] and B[K,N], C[i,j] = Σₖ A[i,k]B[k,j]. The arithmetic is the same, but where arrays live, who schedules work and how results return differ. Start with the real JavaScript product below, then visit each runtime.

  • JavaScript: typed arrays, JIT and loop order.
  • WebAssembly: a real scalar f32 kernel and linear memory; SIMD explained separately.
  • WebGPU: a real WGSL compute dispatch when an adapter is available.
  • LiteRT: model conversion, delegates and a local int8 quantization experiment.
  • PyTorch: runnable Python example plus a JavaScript mirror of reverse-mode autograd.

Enable JavaScript to use this local playground. The explanation and sources below work without it.

Make comparisons fair

A tiny 2 × 2 multiply tests correctness, not throughput. GPU setup and readback dominate at this size. For meaningful benchmarks, warm up kernels, fix shapes and dtypes, synchronize before stopping the timer, separate transfer time from compute time, and check numerical tolerances. Different reduction orders need not be bit-identical.

These pages do not pretend that a JavaScript emulation is native PyTorch or LiteRT. Their runtime requirements and experiment boundaries are explicit.
