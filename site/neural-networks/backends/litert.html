LiteRT on phones and the edge

Understand conversion, delegates and quantization without confusing a numerical demo with model inference.

From a trained graph to an edge runtime

LiteRT is the on-device runtime evolved from TensorFlow Lite. A conversion step packages supported operators, tensor metadata and trained weights into a deployment model, commonly a .tflite FlatBuffer. Conversion can fold constants and apply quantization; it is not the same as training.

A delegate assigns supported subgraphs to an accelerated implementation such as XNNPACK on CPU or a device GPU/NPU backend. Unsupported operators may remain on another path, and crossings between paths can add copies and synchronization. Operator coverage, tensor shapes and hardware availability determine the actual execution plan.

Precision is a deployment choice

Affine quantization represents a real value approximately as (q − zeroPoint)·scale. The demo derives one scale for the whole tensor, includes zero in its range and clamps q to [−128,127]. A large outlier coarsens the step size for every smaller entry.

Real models may use per-channel weight scales and calibration data to estimate activation ranges. Post-training quantization can reduce size and bandwidth, but accuracy must be measured on representative data. Quantization-aware training simulates quantization effects while optimizing weights.

This page executes the quantizer in JavaScript only. It does not download a LiteRT runtime or claim to invoke a phone delegate. For browser decision-model inference integration, see the decision-model playground, which states its model and runtime requirements.
