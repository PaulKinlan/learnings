PyTorch and autograd

Compare a small JavaScript tape with the tensor operations you would run in PyTorch.

Tensors carry values, layouts and history

A PyTorch tensor has a dtype, device, shape and strides. A transpose can change strides without copying storage; a contiguous conversion can allocate. Broadcasting and views affect which elements share storage and how gradients must be summed.

With requires_grad enabled, operations build an autograd graph. Calling backward on a scalar loss propagates vector-Jacobian products, accumulating into leaf parameter gradients. Clear gradients between optimizer steps unless accumulation is intentional. Hooks observe or modify gradients, but careless hooks can retain large graphs.

Enable JavaScript to use this local playground. The explanation and sources below work without it.

Run the corresponding network in Python

The browser graph above is a JavaScript reverse-mode mirror, not PyTorch in the browser. With PyTorch installed locally, run this Python program to compare gradients. It uses float64 to make comparison to JavaScript numbers straightforward.

import torch
x = torch.tensor([1., -2.], dtype=torch.float64)
W = torch.tensor([[.5, -.3], [-.4, .8]], dtype=torch.float64, requires_grad=True)
b = torch.tensor([.1, 0.], dtype=torch.float64, requires_grad=True)
v = torch.tensor([1.2, -.7], dtype=torch.float64, requires_grad=True)
c = torch.tensor(.2, dtype=torch.float64, requires_grad=True)
h = torch.tanh(W @ x + b)
yhat = torch.sigmoid(v @ h + c)
loss = (yhat - 1).square()
loss.backward()
print("prediction", yhat.item(), "loss", loss.item())
print("dL/dW", W.grad, "dL/db", b.grad, "dL/dv", v.grad, "dL/dc", c.grad)
assert torch.isfinite(W.grad).all()
assert W.grad.abs().sum() > 0

torch.compile captures supported regions and optimizes their execution. It does not replace the loss, autograd mathematics or validation. Compilation has startup cost and may encounter graph breaks when Python behaviour cannot be captured.
