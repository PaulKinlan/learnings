WebGPU compute shaders

Dispatch a tiled WGSL matrix multiplication, or see an honest unsupported-device result.

A compute pipeline, not a synchronous function call

WebGPU needs a secure context and a browser/device exposing a suitable adapter. Creating a device, shader module and pipeline precedes dispatch. The existing engine uses 8 × 8 workgroups, storage buffers for matrices and workgroup memory for tiles.

Each workgroup cooperatively loads tiles, waits at a barrier, accumulates products and writes guarded output cells. Out-of-bounds invocations still participate in barriers. Returning some invocations early before a required barrier can deadlock or invalidate a shader.

Enable JavaScript to use this local playground. The explanation and sources below work without it.

Readback has a cost

A storage buffer is not directly a JavaScript array. The engine encodes compute work, copies output to a MAP_READ buffer, submits commands, awaits mapping, copies the bytes and releases buffers. GPU execution is asynchronous. Small operations may cost more in submission and transfer than they save in arithmetic.

This page intentionally does not fall back silently: an unavailable adapter produces an explanatory result. The JavaScript chapter runs everywhere this course runs. The full workbench supports explicit backend comparisons.
